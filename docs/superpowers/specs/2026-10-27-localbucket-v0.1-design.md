# LocalBucket v0.1 设计草案

状态：用户于 2026-10-27 确认整体设计并要求开始开发。此文档不代表 Windows SmartScreen 已解决；发行状态以测试与发布记录为准。

已完成一次只读实施可行性审阅。用户已确认：关闭主窗口即停止共享并退出，不留菜单栏／托盘后台服务。

## 目标与已确认约束

- Mac M4 / macOS 15.7.7 与 Windows 10 x64 独立 App。
- 每台运行软件的电脑拥有软件创建的专用 bucket，数据跨重启保留。
- App 中查看所有在线节点，通过拖入、拖出或明确按钮存取文件。
- 软件绑定固定服务端口，自动发现同一局域网的其他实例，用户无需输入地址。首页第一层展示各电脑名称，点开后才展示该电脑共享的文件。
- 局域网访客无需口令，可浏览、上传、下载；只有 bucket 所属电脑可删除。
- 拖出始终复制／下载，保留源文件。
- Windows 优先单 EXE 双击运行，保持轻量；Mac 为 Apple Silicon App。
- 关闭主窗口即停止本机共享、终止本程序启动的节点服务与 Dufs 子进程并退出；不留托盘后台进程。默认不开机自启。
- 用户已确认原型拖入、拖出验证完成。跨系统自动化测试和后续版本实机回归仍要分别记录。

## 本次选择与替代路线

建议延续已经验证的原生系统拖放：Mac AppKit、Windows Win32/OLE，并抽取共享文件规则与节点服务。现有原型作为行为参照保留，正式产品放在独立目录中，不直接覆盖旧原型。

考虑过的替代路线：Tauri/React 可减少界面重复开发，但 Windows 引入 WebView2 依赖，仍需单独实现已验证的原生拖出桥接；完整自绘跨平台工具包也需额外验证系统拖放。基于现有验证结果和轻量要求，本阶段建议沿用原生界面。此技术取舍是本次提案，等待整体设计确认。

## 防重复行为（用户已确认）

1. 在同一个 bucket／目标目录中，把 App 自己发起的拖拽重新放回：不执行导入，显示“文件已在这里，无需重复添加”。通过本次拖拽的来源标识和规范化源路径识别，而非仅按名称。
2. 文件从 Finder／资源管理器拖回：目标存在同名、同类型、同内容文件则跳过，显示“已跳过 N 个重复文件”。先比较大小，再流式计算内容哈希，避免一次读入大文件。
3. 同名但内容不同：自动保留两份，使用扩展名前编号，按“保留为 文件名 (1).扩展名”提示，不弹窗。
4. 已存在的编号副本也参与同名冲突组内容检查，重复导入同一份改动文件不会不断生成 (2)、(3)。仅在同一目标目录的该文件名冲突组中去重，不进行全库内容合并。
5. 目录导入采用逐项合并：相同内容子文件跳过，新文件导入，冲突内容自动编号。文件与目录同名时为新项目编号；不覆盖旧内容。
6. 拒绝把 bucket 根目录／目标祖先目录递归导入自身；规范化路径识别同路径与硬链接，v0.1 不跟随符号链接／Windows reparse points。
7. 远端导入使用同一规则，由目标节点执行最终冲突判断与原子提交。并发同名上传通过目标端串行提交或独占创建重新选名，禁止覆盖。
8. 取消或失败上传仅留下内部临时项目，不把半成品列为可下载文件；本次不删除已存在的用户文件。

## 界面与指引

整体方向：浅色、中性背景、少量强调色、清晰文件图标与足够留白。中文默认，展示产品名称 LocalBucket。

- 首页第一层：展示“我的电脑”和其他已自动发现的在线电脑，使用实际电脑名称，本机附“本机”标记。设备 ID 用于区分重名电脑；无地址输入框或手动连接步骤。
- 点开一台电脑：进入其 bucket 文件列表。顶部显示“所有电脑 > 电脑名称 > 当前文件夹”导航、文件搜索／过滤、刷新、“添加文件”。主界面不出现 Dufs、端口调试信息和 LOCAL/REMOTE 测试标签。
- 文件层：采用可滚动、可多选的原生控件，列出名称、大小和修改时间；支持进入文件夹和返回上级，也能直接返回“所有电脑”。不把多台电脑的文件混在同一个目录。
- 空状态：进入空 bucket 后醒目标注“把文件或文件夹拖到这里”，附“添加文件”按钮；首页未发现其他节点时显示“正在寻找附近的电脑”，提供重新搜索及网络诊断，提示确认软件在对方电脑运行、同一局域网和系统网络授权，不要求输入 IP。
- 拖拽目标：在首页尚未选中电脑时不接收文件导入，提示先打开目标电脑；进入某台电脑的文件列表后，拖入才存到该电脑的 bucket。
- 拖入期间：显示明显投放高亮和“添加到「目标 bucket」”，用户能在放下前确认目标电脑。
- 拖出：选中文件后提示“拖到桌面或文件夹即可复制，原文件保留”；提供“另存到…”按钮作为无拖拽操作入口。
- 底部任务区：文件名称、进度、成功／跳过／失败数量、可执行的重试操作；错误信息在刷新后保留，避免被通用 Ready 覆盖。
- 本机文件：显示删除操作，使用系统回收站；远端文件不显示删除入口，服务端也拒绝删除。
- 所有主要操作提供可访问名称和键盘入口；窗口缩放、长文件名和大量文件不遮挡操作按钮。
- 首次运行以简短内嵌指引说明“本机 bucket”“附近电脑”“拖入存放／拖出复制”；可以关闭并从帮助重新打开。

## 进程与服务

建议采用共享 Go 节点服务负责发现、列表、导入冲突规则、传输任务、持久配置与 Dufs 生命周期。Mac 原生界面通过仅本机可用的受控接口调用服务；Windows 可在同一 EXE 内运行节点服务。Dufs 使用固定版本，作为内部文件处理组件，仅监听 loopback。

局域网接口只暴露节点发现、授权范围内的目录列举和文件读写；本机管理接口使用启动时建立的凭证并检查连接来源。不能因为入口节点代理了某个请求，就把远端访客升级成本机管理者。删除权限由目标节点最终检查。

节点服务默认使用 TCP 47931；进程内检测单实例，重复打开聚焦已有窗口。端口被其他程序占用时显示具体错误与重试入口，不静默启动第二个冲突服务。内部 Dufs 使用独立 loopback 端口，不争用节点对外服务端口。

设备通过 mDNS 公布固定端口服务（类型 `_localbucket._tcp`），通过局域网 UDP 广播查询／响应作为发现补充，协议中携带版本、设备 ID、电脑名称与服务端口。枚举有效物理局域网接口，处理多网卡、IP 变化、休眠唤醒与网络切换。发现后通过节点 API 验证服务身份与协议版本；过期和主动下线更新在线列表。每个节点有持久设备 ID，名称或 IP 变化不生成新身份。固定端口本身不等于发现机制；组播／广播均不可达或路由器隔离客户端时，通过诊断说明网络限制，不能保证所有 WiFi 环境都能互访。

关闭主窗口时停止接受新任务，取消仍在进行的网络传输，保留已完成文件与持久配置，隐藏或清理本次未提交的临时文件，并注销发现服务、关闭服务端监听、终止本程序创建的子进程。若仍有活动任务，提示此次关闭将中断传输；用户确认后退出，可取消关闭继续传输。其他节点将本机更新为离线。异常退出后的残留临时项目由下次启动恢复检查处理，禁止把半成品显示为正常文件。

v0.1 访问只限可达的局域网，不提供公网穿透。元数据与文件采用统一节点 API，浏览 UI 与网络传输解耦，不需要固定中心节点。文件采用流式读写，进度通过事件更新，不在 UI 主线程执行网络或哈希。

保留原型的本机拖出与 Mac 文件承诺机制；Windows 的远端拖出需在后台准备缓存，并显示准备状态。正式版不在 OLE GetData 回调中阻塞下载。大文件第一次拖出若尚未准备好，显示明确准备状态和“另存到…”入口，之后拖出使用有效缓存。本次不承诺 Windows 已具备虚拟文件的完整异步文件承诺。

## 数据与迁移

正式版使用独立 LocalBucket 数据目录。首次启动若发现 LocalBucketDragSpike 数据，提示是否复制导入；不静默移动、删除或共享旧测试文件。配置、日志、缓存与 bucket 分开存放；EXE 更新不会清空数据。

用户可以从本机“打开存储位置”查看专用文件夹。通过系统文件管理器增删文件后，App 刷新／文件监控可反映变化。缓存有容量与过期清理策略，但不得清理仍被系统拖放引用的文件。

## Windows 启动与发行

用户确认拦截为 SmartScreen。它涉及发行者签名和文件下载信誉，改图标、改文件名、ZIP 包装或自签名不能保证消除提示。

v0.1 工程内加入稳定发布者／版本元数据、图标、可选 Authenticode 签名与时间戳步骤，保留校验和，不使用加壳压缩。嵌入的内部可执行文件也纳入签名流程；先签内部文件，再构建／签外层 EXE，签名后不修改产物。

有受信任签名证书或签名服务后才能产出可信发行者签名版本。凭证只从安全的本机／CI 配置读取，不提交仓库。申请服务、付费、身份验证需要用户决定，本次不自动购买或提交身份信息。

微软说明有效签名的新程序仍可能显示 SmartScreen 提示，不能承诺立即免提示；Microsoft Store 分发是另一个后续发行选项。v0.1 发布说明必须区分“签名有效”与“已实测无提示”，不关闭或绕过系统保护。

## 图标

按用户要求使用内置 imagegen 生成预览：单个简洁存储桶，放置文件卡片，以克制的流动形态表达存取，透明外背景，无文字和细碎装饰。预览供用户审阅；选定后保留 PNG 母版，再输出 Windows ICO 和 Mac ICNS，嵌入程序、窗口与发行包。不要把生成预览当作已完成系统图标集成。

## 验收

- 同一 App 内拖回、文件导出后原样拖回、连续重复导入、改动同名文件再次导入，均符合上述跳过／自动保留规则。
- 覆盖文件夹、Unicode／中文、Win 大小写碰撞、空文件、长文件名、并发上传、目录递归导入保护和网络中断。
- 上传、哈希、下载不会阻塞主界面；错误与跳过有清晰结果。
- Mac 与 Win10 实机分别回归原生拖入／拖出，并完成双向跨机传输。
- 远端请求无法删除文件或访问 bucket 以外目录。
- 从 GitHub 下载的最终 Windows 产物检查 Authenticode 状态，并记录 SmartScreen 实际提示；无证书时不声称免拦截。
- 安装包／EXE 大小、内存、启动依赖实测后记录，不预设具体数字。

## 本次不加入

公网访问、跨节点自动同步／副本、全库去重、媒体转码、自动更新、购买签名证书或申请商店账户。
